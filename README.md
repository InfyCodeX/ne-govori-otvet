<h1 align="center">Не говори ответ</h1>

<p align="center">ИИ-наставник, который помогает разобраться в своей ошибке и решить задачу самостоятельно.</p>

<p align="center">
  <a href="https://max.ru/ideya_fiks_106_bot">Открыть в MAX</a> ·
  <a href="http://127.0.0.1:8000/">Веб-тренажёр</a> ·
  <a href="https://github.com/InfyCodeX/ne-govori-otvet/releases/latest">Скачать Docker-образ</a>
</p>

Проект команды «Кодоворот» для хакатона «Идея фикс». Ученик присылает своё решение текстом или фотографией, а бот помогает найти место, где возникла ошибка. Затем можно выбрать подсказку, исправить решение своими словами и закрепить навык на похожей задаче.

В презентации проект рассчитан на школьников 5–11 классов. Текущий математический MVP отрабатывался прежде всего на заданиях 5–9 классов.

## Что умеет бот

| Функция | Как она помогает |
| --- | --- |
| **Где я свернул не туда?** | Показывает первое ошибочное действие и цитирует запись ученика. |
| **Не говори ответ** | Предлагает намёк, подсказку или подробный разбор правила. Помощь усиливается постепенно, готовый итоговый ответ остаётся скрыт. |
| **Поймай свою ошибку** | Проверяет исправленное действие и объяснение. Можно отвечать обычным сообщением, без обязательной нумерации. |
| **Реванш** | После завершения решения предлагает похожую задачу для самостоятельной работы. |
| **Карта слабых мест** | Сохраняет ошибки, исправления и подсказки по темам, показывает динамику и позволяет выбрать тренировку. |

Перед проверкой фотографии бот показывает распознанное условие и действия. Если запись прочитана неточно, её можно исправить. Когда информации недостаточно, бот просит уточнение. Некорректные вложения, явные оскорбления и попытки сменить правила работы получают отдельный ответ.

Веб-тренажёр использует ту же учебную логику. Ссылка на него открывается на компьютере, где запущен контейнер.

## Как всё устроено

Приложение использует клиент-серверную архитектуру. Ученик общается с ботом в MAX или открывает веб-тренажёр. Сервер принимает сообщение, ведёт текущую задачу, обращается к ИИ и сохраняет учебный прогресс.

~~~mermaid
flowchart LR
    Student["Ученик"] --> MAX["MAX"]
    Student --> Browser["Веб-тренажёр"]
    MAX <-->|"MAX Bot API"| Server["Сервер Python / FastAPI"]
    Browser <-->|"HTTP"| Server
    Server <-->|"Responses API"| AI["Yandex AI Studio"]
    Server --> Math["Точная математическая проверка"]
    Server <--> DB[("SQLite")]
~~~

| Часть проекта | Технологии и назначение |
| --- | --- |
| Веб-интерфейс | HTML, CSS и JavaScript. Отправка текста и фото, кнопки помощи, отображение ответов. |
| Сервер | Python, FastAPI и Uvicorn. Общая логика бота и веб-тренажёра. Pydantic проверяет структуру данных. |
| Интеграции | MAX Bot API для сообщений и кнопок, Yandex AI Studio через Responses API для работы с моделью. Запросы отправляются через HTTPX. |
| Математика | Собственные проверяющие модули, точная рациональная арифметика Python и SymPy. |
| Данные и запуск | SQLite хранит сессии и прогресс. Pillow обрабатывает фотографии. Docker Compose запускает приложение в контейнере. |

ИИ распознаёт фотографии и свободный текст, проверяет решения, готовит пояснения, разбирает исправления и оценивает объяснения ученика. Известные типы вычислений дополнительно проверяются локальными математическими модулями. Для однозначных случаев они могут полностью выполнить проверку без облачного запроса. При выборе уже подготовленной подсказки или открытии карты новый запрос к модели обычно не требуется.

Тема привязана к первой ошибке. Если подходящей категории в каталоге нет, ИИ получает существующие темы и может предложить новую конкретную категорию. Новое тренировочное условие создаётся моделью и отдельно проверяется на соответствие навыку и достаточность данных. Для известных тем предусмотрены резервные упражнения. История условий сохраняется, чтобы повторно не выдавать ученику ту же задачу после смены темы или перезапуска.

В `app/main.py` находятся HTTP-маршруты и запуск службы, в `app/dashboard.html` — веб-интерфейс. `app/learning.py` ведёт учебный сценарий, `app/submissions.py` разбирает запись ученика, `app/skills.py` работает с темами. Математические проверки вынесены в отдельные модули. `app/integrations/` содержит подключения к MAX и Яндексу, а `app/storage.py` — работу с базой.

Для подключения другого ИИ или хранилища можно реализовать соответствующий интерфейс из `app/domain.py` и подключить его при запуске. Другой канал общения может вызывать те же методы учебного сервиса, что MAX и браузер. Это позволяет расширять проект, сохраняя общий сценарий работы с задачей.

## Запуск

Нужны Docker Desktop с Linux-контейнерами и интернет. Скачайте проект и откройте терминал в его папке. Команды ниже рассчитаны на PowerShell.

При первом запуске создайте файл настроек.

~~~powershell
Copy-Item .env.example .env
~~~

С настройками из шаблона откроется веб-тренажёр с учебным примером. Для MAX и работы со своими задачами заполните `.env` по таблице ниже.

Соберите образ и запустите приложение.

~~~powershell
docker compose build
docker compose up -d --wait
docker compose ps
~~~

После запуска откройте [веб-тренажёр](http://127.0.0.1:8000/). В режиме MAX этот же контейнер обслуживает чат-бота. Одновременно запускать второй экземпляр с тем же токеном не нужно.

Готовый образ доступен в [релизе проекта](https://github.com/InfyCodeX/ne-govori-otvet/releases/latest). Положите скачанный файл `ne-govori-otvet.tar` в папку проекта и запустите его без сборки.

~~~powershell
docker image load -i .\ne-govori-otvet.tar
docker compose up -d --no-build --wait
~~~

Журнал работы и остановка приложения доступны из Docker Desktop. Те же действия можно выполнить в терминале.

~~~powershell
docker compose logs -f --tail 50 bot
docker compose stop
~~~

База хранится в томе `ne-govori-otvet_bot-data` и сохраняется после остановки и обновления контейнера. При новой установке создаётся пустая база.

## Настройки подключения

Файл `.env` находится в корне проекта. В репозитории есть `.env.example` с образцом настроек. Рабочие токены и ключи передаются комиссии отдельно для закрытой проверки.

| Параметр | Что указать |
| --- | --- |
| `BOT_MODE` | `demo` для веб-тренажёра или `max` для подключения чат-бота. |
| `MAX_BOT_TOKEN` | Токен, предоставленный для бота в MAX. |
| `EXPECTED_BOT_USERNAME` | Имя бота. Для проекта — `ideya_fiks_106_bot`. |
| `MAX_CA_BUNDLE` | Путь к дополнительному доверенному сертификату MAX, если он нужен. Например, `certs/russian_trusted_root_ca_pem.crt`. Папка `certs/` подключается к контейнеру только для чтения. |
| `AI_ENABLED` | `true` для обработки собственных задач через ИИ. |
| `AI_OWNER_MANAGED` | `true`, если владелец самостоятельно контролирует баланс облачного аккаунта. |
| `YANDEX_API_KEY` | API-ключ Yandex AI Studio с доступом к выбранной модели. |
| `YANDEX_MODEL_URI` | Идентификатор модели, например `gpt://<folder-id>/qwen3.6-35b-a3b`. |
| `DATABASE_PATH` | При запуске через Python — `data/bot.sqlite3`. В Docker путь задаётся автоматически. |
| `LOG_LEVEL` | Обычно `INFO`. Журнал показывает команды, обращения к ИИ и доставку ответов. |
| `ENABLE_AI_SETUP` | Обычно `false`. Включает локальную страницу настройки ИИ при необходимости. |

Сертификат можно получить по [официальной инструкции MAX](https://dev.max.ru/docs-api). Для работы через Long Polling у бота не должно быть активной Webhook-подписки.

## Данные и возможности MVP

Основное направление — школьная математика. Поддерживаются числовые выражения, дроби, проценты, округление по условию, уравнения, отдельные символьные преобразования, неравенства, линейные системы, значения функций, текстовые задачи, вероятность и статистика. Полное покрытие школьной программы и проверка построенных рисунков требуют дальнейшего развития.

Можно отправить текст или одну фотографию JPEG, PNG либо WebP до 8 МБ. Голосовые сообщения и документы не входят в поддерживаемый ввод. Фото обрабатывается в памяти и не сохраняется. Текст и фото передаются в Yandex AI Studio, а текущая задача и учебный прогресс хранятся в SQLite.

`/reset` начинает новую задачу, сохраняя карту. `/forget` удаляет личную учебную статистику и историю условий. После удаления данных прежние задания могут встретиться снова. Не отправляйте персональные данные.

MVP работает с облачной моделью, поэтому качество распознавания и проверки зависит в том числе от её ответа. Для поддержанных математических записей используются дополнительные точные проверки, а при неоднозначности бот просит уточнение.
