<h1 align="center">Не говори ответ</h1>

<p align="center">Чат-бот с ИИ для проверки решения и самостоятельной работы над ошибками.</p>

<p align="center">
  <a href="https://max.ru/ideya_fiks_106_bot">Чат-бот в MAX</a> ·
  <a href="http://127.0.0.1:8000/">Web-тренажёр</a> ·
  <a href="https://github.com/InfyCodeX/ne-govori-otvet/releases/latest">Docker-образ</a>
</p>

Проект команды «Кодоворот».

## Сценарий использования

Ученик присылает своё решение текстом или фотографией, а бот помогает найти место, где возникла ошибка. Затем можно выбрать подсказку, исправить решение своими словами и закрепить навык на похожей задаче.

Проект рассчитан на учащихся 5–11 классов. В текущем MVP реализована работа с заданиями по математике. Поддерживаются числовые выражения, дроби, степени и квадратные корни, проценты, округление по условию, уравнения, отдельные символьные преобразования, неравенства, линейные системы, значения функций, текстовые задачи, вероятность и статистика. Проверка чертежей, графиков и задания по другим дисциплинам требуют дальнейшей разработки.

Поддерживаемый ввод — текст или одна фотография в формате JPEG, PNG или WebP до 8 МБ.

## Навыки чат-бота «Не говори ответ»

| Функция | Назначение |
| --- | --- |
| **Где я свернул не туда?** | Показывает первое ошибочное действие и цитирует запись ученика. |
| **Не говори ответ** | Предлагает намёк, подсказку или подробный разбор правила без готового итогового ответа. |
| **Поймай свою ошибку** | Проверяет исправленное действие и объяснение ученика. Отвечать можно в свободной форме. |
| **Реванш** | После завершения решения предлагает похожую задачу по отработанному навыку. |
| **Карта слабых мест** | Сохраняет статистику по ошибкам, исправлениям, завершённым задачам и подсказкам. Показывает динамику и позволяет выбрать тему для тренировки. |

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Знакомство с ботом и справка по командам. |
| `/example` | Учебный пример с ошибкой. |
| `/first_error` | Первое ошибочное действие. |
| `/hint` | Выбор уровня помощи. |
| `/discover` | Самостоятельное исправление ошибки. |
| `/rematch` | Похожая задача после завершения решения. |
| `/map`, `/practice` | Карта слабых мест и выбор темы тренировки. |
| `/reset` | Новая задача с сохранением карты и истории упражнений. |
| `/forget` | Удаление личной учебной статистики, текущей задачи и истории упражнений. |

Перед проверкой фотографии бот показывает распознанное условие и действия. Ученик может подтвердить запись или прислать исправленный вариант. При неоднозначной записи бот просит уточнение. Для неподдерживаемых вложений, явно некорректных сообщений и попыток сменить правила работы предусмотрены отдельные ответы.

В MAX кнопки остаются под актуальным сообщением. Из меню подсказок, карты слабых мест и списка тем можно вернуться к текущей задаче кнопкой «Назад».

Вычисления проверяются гибридно. Локальные модули могут самостоятельно проверить поддерживаемые арифметические записи, в том числе цепочки равенств. Модель ИИ распознаёт фотографии, разбирает свободный текст, проверяет пояснения и задачи, для которых требуется разбор по смыслу. Если сложную запись не удаётся проверить целиком, бот предлагает прислать часть вычислений или начать новую задачу.

Тема в карте слабых мест относится к первому ошибочному действию. Модель ИИ учитывает существующие категории и при необходимости предлагает название для нового навыка. Модель составляет тренировочную задачу, а отдельная проверка оценивает её соответствие теме и достаточность данных. Для известных тем предусмотрены резервные упражнения. Бот сверяет условия с сохранённой историей при повторной тренировке, смене темы и после перезапуска.

В Web-тренажёре доступны те же учебные сценарии, что и в чат-боте MAX. Тренажёр открывается по ссылке после запуска Docker-контейнера.

## Архитектура чат-бота «Не говори ответ»

Приложение использует клиент-серверную архитектуру. Ученик общается с чат-ботом в MAX или открывает Web-тренажёр. Сервер принимает сообщения, обрабатывает задачу, обращается к ИИ и сохраняет учебный прогресс.

~~~mermaid
flowchart LR
    U["Ученик отправляет условие и решение"]
    U --> MAX["Чат в MAX"]
    U --> WEB["Web-тренажёр"]
    MAX -->|"MAX Bot API"| S["Сервер Python / FastAPI"]
    WEB -->|"HTTP"| S
    S --> IN{"Формат ввода"}
    IN -->|"Фото"| OCR["Yandex AI Studio · распознавание"]
    OCR --> CONF["Ученик подтверждает или исправляет запись"]
    CONF --> CHECK["Сервер разбирает действия"]
    IN -->|"Текст"| CHECK
    CHECK -->|"Поддерживаемое вычисление"| M["Точная проверка · Python и SymPy"]
    CHECK -->|"Нужна проверка моделью"| AI["Qwen · Yandex AI Studio Responses API"]
    M --> R{"Результат проверки"}
    AI --> R
    R -->|"Найдена ошибка"| H["Первое ошибочное действие или подсказка"]
    H --> FIX["Ученик исправляет действие и объясняет правило"]
    FIX --> CHECK
    R -->|"Нужны уточнения или следующие действия"| U
    R -->|"Решение завершено"| REMATCH["Реванш по отработанному навыку"]
    R --> DB[("SQLite · сессия и прогресс")]
    DB --> MAP["Карта слабых мест"]
    MAP -->|"Выбор темы"| GEN["Подбор и проверка новой задачи"]
    REMATCH --> GEN
    GEN -->|"Модель или резервное упражнение"| U
~~~

| Часть проекта | Технологии и назначение |
| --- | --- |
| **Клиент** | HTML, CSS и JavaScript для Web-тренажёра. Интерфейс принимает текст и фото, показывает кнопки помощи и ответы. |
| **Сервер** | Python, FastAPI и Uvicorn. Сервер обрабатывает запросы бота и Web-тренажёра. Библиотека Pydantic проверяет структуру данных. |
| **Интеграции** | MAX Bot API для сообщений и кнопок. Yandex AI Studio Responses API для модели Qwen3.6-35B-A3B. Запросы отправляются через HTTPX. |
| **Гибридная проверка** | Облачная модель, собственные модули проверки, точная рациональная арифметика Python и библиотека SymPy. |
| **Данные и запуск** | СУБД SQLite хранит сессии и прогресс. Библиотека Pillow обрабатывает фотографии. Docker Compose запускает приложение в контейнере. |

### Хранение данных в SQLite

Учебные записи связываются по полю `learner`. Оно содержит хеш канала и идентификатора пользователя. У MAX и Web-тренажёра отдельные сессии. В SQLite сохраняется распознанный текст, а сама фотография обрабатывается в памяти.

| Таблицы | Что записывается |
| --- | --- |
| `learning_sessions` | Текущая задача ученика с условием, действиями и результатом проверки. Запись позволяет продолжить работу после перезапуска. |
| `skill_progress` | Итоговые счётчики по каждой теме ученика для карты слабых мест. |
| `learning_observations` | Учебные события с датами. По ним карта сравнивает последние семь дней с предыдущими семью. |
| `learning_topics` | Новые темы ученика, которые появились при разборе ошибок. |
| `learning_exercises` | Хеши условий, то есть короткие отпечатки записей. По ним бот распознаёт уже встречавшиеся задания. |
| `events` | Сведения об обработанных событиях MAX, чтобы повторная доставка не вызывала повторного ответа. |
| `metadata` | Служебные данные MAX, в том числе позиция в очереди событий и последнее меню в чате. |
| `ai_usage`, `learner_ai_usage` | Число запросов к ИИ за сутки по всему боту и по каждому ученику. Используется в режиме локальных ограничений. |
| `ai_budget` | Резерв суммы перед запросом к ИИ и оценка стоимости по токенам после ответа. Таблица помогает соблюдать заданный бюджет. При `AI_OWNER_MANAGED=true` этот учёт не применяется. |

Условие и действия в поле `state` выглядят, например, так.

~~~json
{
  "problem": "7 + 12",
  "steps": ["7 + 12 = 20"],
  "awaiting_correction": true
}
~~~

## Запуск через Docker

Команды приведены для PowerShell. Их нужно выполнять из корня проекта.

При первом запуске, если файла `.env` ещё нет, нужно скопировать образец настроек.

~~~powershell
Copy-Item .env.example .env
~~~

Команда создаёт рабочий `.env` на основе файла `.env.example`. С настройками из образца доступен Web-тренажёр с учебным примером. Для подключения к MAX и работы со своими задачами нужно заполнить `.env` по таблице. Рабочие токены и ключи могут быть переданы отдельно для проверки.

| Параметр | Данные для ввода |
| --- | --- |
| `BOT_MODE` | `demo` для Web-тренажёра или `max` для подключения чат-бота. |
| `MAX_BOT_TOKEN` | Токен, предоставленный для бота в MAX. |
| `EXPECTED_BOT_USERNAME` | Имя бота. Для проекта используется `ideya_fiks_106_bot`. |
| `MAX_CA_BUNDLE` | Путь к дополнительному доверенному сертификату MAX, если он нужен. Пример — `certs/russian_trusted_root_ca_pem.crt`. Папка `certs/` подключается к контейнеру только для чтения. |
| `AI_ENABLED` | `true` для обработки собственных задач через ИИ. |
| `AI_OWNER_MANAGED` | `true`, если владелец самостоятельно контролирует баланс облачного аккаунта. Для локального контроля можно задать `false`, `AI_DAILY_REQUEST_LIMIT` и `AI_TRIAL_BUDGET_RUB`. |
| `YANDEX_API_KEY` | API-ключ Yandex AI Studio с доступом к выбранной модели. |
| `YANDEX_MODEL_URI` | Идентификатор модели. Пример — `gpt://<folder-id>/qwen3.6-35b-a3b`. |
| `DATABASE_PATH` | При запуске через Python используется `data/bot.sqlite3`. В Docker путь задаётся автоматически. |
| `LOG_LEVEL` | Обычно `INFO`. Журнал показывает команды, обращения к ИИ и отправку ответов. |
| `ENABLE_AI_SETUP` | Обычно `false`. При необходимости можно включить локальную страницу настройки ИИ. |

Сертификат можно получить по [инструкции MAX](https://dev.max.ru/docs-api). Для работы через Long Polling требуется отключить активную Webhook-подписку бота.

### Сборка и запуск из исходников

~~~powershell
docker compose build
docker compose up -d --wait
docker compose ps
~~~

- `docker compose build` собирает образ из исходников.
- `docker compose up` запускает контейнер. Ключ `-d` оставляет его работать в фоне, а `--wait` ждёт готовности.
- `docker compose ps` показывает состояние контейнера и его порт.

После запуска доступен [Web-тренажёр](http://127.0.0.1:8000/). В режиме `max` этот же контейнер обслуживает чат-бота. На один токен нужен один экземпляр приложения.

### Запуск готового образа

Готовый образ доступен в [релизе проекта](https://github.com/InfyCodeX/ne-govori-otvet/releases/latest). Скачанный файл `ne-govori-otvet.tar` нужно положить в папку проекта.

~~~powershell
docker image load -i .\ne-govori-otvet.tar
docker compose up -d --no-build --wait
~~~

- `docker image load -i` загружает образ из указанного архива.
- `docker compose up` запускает контейнер из загруженного образа. Ключ `--no-build` пропускает сборку.

### Журнал и остановка

~~~powershell
docker compose logs -f --tail 50 bot
docker compose stop
~~~

- `docker compose logs` открывает журнал службы `bot`. Ключ `--tail` со значением `50` выводит последние 50 строк, а ключ `-f` продолжает выводить новые записи.
- `docker compose stop` останавливает контейнер.

База данных SQLite хранится в томе `ne-govori-otvet_bot-data`. Сессии и прогресс сохраняются после остановки или обновления контейнера. При первом запуске с новым томом создаётся пустая база данных.
